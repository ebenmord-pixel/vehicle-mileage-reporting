# מערכת לניהול תחקירים ומעקב שיפורים

אפליקציית ווב בעברית (RTL) לניהול תחקירים מקצה לקצה: תיאור האירוע, איסוף התייחסויות מהמחלקות, הצגה בישיבה, ממצאים ומסקנות, משימות לשיפור ומעקב עד סגירה.

## תהליך העבודה

1. **פתיחת תחקיר — "מה קרה?"**: המשתמש הראשון מתאר את האירוע (פרטים, חומרה, השפעה, פעולות מיידיות, ציר זמן) וקובע Owner לתחקיר.
2. **הקצאת משתתפים לפי מחלקות**: בוחרים מחלקות (אפשר מחלקה שלמה בלחיצה) ובתוכן את המשתמשים שיש להם חלק בתקלה. כל משתמש מקבל מייל עם **קישור אישי** למילוי החלק שלו (לא צריך התחברות).
3. **כל משתתף ממלא את חלקו**: מה קרה מנקודת מבטו, פעולות שבוצעו, גורמים, מה עבד, מה לשפר, הצעות וציר זמן משלו. אפשר לשמור טיוטה ולהגיש. כשכולם הגישו, התחקיר עובר אוטומטית לסטטוס "מוכן לישיבה".
4. **ישיבת תחקיר — הצגה מתוך המערכת**: מצגת במסך מלא (חיצים, מקלדת, שעון ישיבה). במצב "עריכה בישיבה" ממלאים בזמן אמת ממצאים (סוג, גורם שורש, מחלקה), מסקנות, משימות וסיכום.
5. **משימות ומעקב**: לכל משימה יש Owner, תאריך יעד, עדיפות, אחוז התקדמות, סטטוס, מדד הצלחה והיסטוריית הערות. המשימות מקושרות למסקנה ולתחקיר.

## מסכים עיקריים

| מסך | תיאור |
|---|---|
| לוח בקרה | מה ממתין למילוי שלי, המשימות שלי, משימות באיחור, התפלגויות וגורמי שורש חוזרים |
| **טבלת מעקב שיפורים** (`/tracking`) | כל התחקירים בטבלה אחת: מצב (🔴🟡🟢), Owner, התייחסויות, ממצאים, משימות, באיחור, היעד הקרוב ואחוז התקדמות. אפשר להרחיב שורה ולעדכן אחוזים ישירות מהטבלה, ולייצא לאקסל |
| תחקירים | רשימה עם סינון, ובתוך תחקיר: פרטים, משתתפים, התייחסויות, ישיבה, ממצאים, מסקנות, משימות, נספחים ויומן פעילות |
| משימות לשיפור | תצוגת טבלה או לוח (Kanban), סינון לפי Owner, מחלקה, תחקיר ואיחור, ויצוא לאקסל |
| ניהול | משתמשים (כולל ייבוא בהדבקה מאקסל), מחלקות ומנהלי מחלקות, הגדרות תזכורות |

## נספחים

לכל תחקיר אפשר לצרף קבצים (תמונות, PDF, Office ועוד, עד 25MB לקובץ). כל משתתף בתחקיר יכול להעלות קבצים. תמונות שסומנו "הצג במצגת" מוצגות בשקף "נספחים", ואפשר להגדיל אותן בלחיצה. הקבצים נשמרים ב-`data/uploads/`.

## תזכורות במייל — כל X ימים

| תזכורת | למי | ברירת מחדל |
|---|---|---|
| משימה פתוחה | Owner המשימה | כל 7 ימים (אפשר לקבוע ערך אחר לכל משימה, 0 = ללא) |
| משימה באיחור | Owner המשימה | כל 2 ימים |
| טרם מילא את חלקו | משתתף בתחקיר | כל 2 ימים (אפשר לקבוע ערך אחר לכל תחקיר) |
| סיכום Owner | Owner התחקיר: משימות באיחור ומי שטרם מילא | כל 7 ימים |

את הערכים ואת שעת השליחה מגדירים ב**ניהול ← תזכורות ומיילים**. התזכורות נשלחות בימים א׳–ה׳. באותו מסך יש גם כפתור "הרצה עכשיו" וכפתור לשליחת מייל בדיקה. בכל משימה ובטבלת המעקב יש גם כפתור ✉ לשליחת תזכורת מיידית.

## הצגה וייצוא

- **הצגה מתוך המערכת** היא הדרך הראשית: הכפתור "▶ הצגה בישיבה".
- ייצוא הוא אפשרות משנית בלבד, בתפריט "ייצוא": **PowerPoint** (באותו מבנה שקפים) או **הדפסה / PDF**.
- מבנה השקפים (סדר, כותרות, הסתרה) מוגדר במקום אחד: `src/slides.js`. השדות שכל משתתף ממלא מוגדרים ב-`src/constants.js` (`RESPONSE_FIELDS`). כך אפשר להתאים בקלות למבנה המצגת הארגונית.

## התקנה והרצה

דרוש Node.js מגרסה 18 ומעלה.

```bash
cd debrief-system
npm install
cp .env.example .env   # ולמלא פרטי SMTP
npm start
```

כתובת ברירת המחדל: http://localhost:3100

**התחברות ראשונית:** משתמש `admin`, סיסמה `admin123`. **יש להחליף את הסיסמה מיד** בעמוד "הפרופיל שלי".

### מיילים (Microsoft 365 / Outlook)

ממלאים בקובץ `.env` את `SMTP_USER`, `SMTP_PASS` ו-`MAIL_FROM`, וגם את `APP_BASE_URL`, כדי שהקישורים במיילים יפנו לכתובת האמיתית של השרת. כל עוד SMTP לא מוגדר, המיילים לא נשלחים אלא נרשמים בקובץ `data/outbox.log`. בינתיים אפשר להעתיק לכל משתתף את הקישור האישי שלו (כפתור 🔗).

## הרשאות

- **מנהל מערכת**: הכול.
- **Owner / פותח התחקיר**: ניהול מלא של התחקיר.
- **משתתף**: צפייה בתחקיר, מילוי החלק שלו והעלאת נספחים.
- **Owner משימה**: עדכון התקדמות והערות.

## נתונים

כל הנתונים נשמרים ב-`data/db.json`, והקבצים ב-`data/uploads/`. מומלץ לגבות את התיקייה `data/` באופן קבוע.
